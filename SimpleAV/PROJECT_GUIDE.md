## 1. Обзор проекта

**TEAV** — исследовательский антивирус для Windows. Цель проекта — продемонстрировать три классических метода обнаружения вредоносного программного обеспечения без использования готовых антивирусных движков или внешних баз данных репутации.

### Три метода обнаружения

| Метод | Суть | Когда срабатывает |
|-------|------|-------------------|
| **Сигнатурный** | Сравнение хэша файла с базой известных вирусов | Точное совпадение — 100% уверенность |
| **Статический** | Анализ структуры PE-файла без его запуска | Всегда, если файл является PE |
| **Эвристический** | Накопление баллов по подозрительным признакам | Вычисляется на основе результатов статики |

### Ключевые принципы архитектуры

- **Ранняя остановка при сигнатуре.** Если хэш файла найден в базе, дальнейший анализ не запускается — результат однозначен.
- **Однонаправленный поток.** Каждый модуль получает данные, возвращает результат и не знает о существовании других модулей. Единственная точка сборки — `Scanner.cs`.
- **Самописный PE-парсер.** Весь разбор формата PE написан вручную без внешних библиотек — это часть демонстрации навыка.
- **Минимум внешних зависимостей.** NuGet-пакеты только там, где писать самому не имеет смысла (CLI-парсинг, JSON-сериализация).

### Платформа

- **ОС:** Windows 7 SP1 и выше
- **Runtime:** .NET Framework 4.7.2
- **Язык:** C# 7.3
- **Сборка:** `dotnet build -c Release`

### Почему такое разделение

`Core/` содержит то, что не зависит от конкретного формата файла — оркестрацию и инфраструктуру. `Modules/` — детекторы, каждый из которых отвечает за свою область. Такое разделение позволяет добавить, например, анализ PDF или Office-документов, не трогая ядро.

### 3.2 `Program.cs`

**Что делает:** точка входа программы. Отвечает за три вещи: разбор аргументов командной строки, форматированный вывод результатов, интерактивный промпт действий (карантин / удалить / пропустить).

**Ключевые части:**

```csharp
static int Main(string[] args)
{
    return Parser.Default
        .ParseArguments<Options>(args)
        .MapResult(Run, _ => 1);
}
```

`Parser.Default.ParseArguments` — это CommandLineParser. При ошибке в аргументах он автоматически печатает справку и возвращает код 1. `MapResult` вызывает `Run` если парсинг успешен.

```csharp
class Options
{
    [Value(0, Required = true)]  public string Path { get; set; }
    [Option('r', "recursive")]   public bool Recursive { get; set; }
    [Option('q', "quarantine")]  public bool AutoQuarantine { get; set; }
    [Option('d', "delete")]      public bool AutoDelete { get; set; }
    [Option("db")]               public string DbPath { get; set; }
    [Option("min-score", Default = 70)] public int MinScore { get; set; }
}
```

`--min-score` позволяет менять порог действия не трогая код: например, при исследовании выборки удобно поставить `--min-score 30` чтобы видеть всё подозрительное.

**Логика вывода при сканировании папки:** результаты накапливаются в список, прогресс показывается в одну перезаписываемую строку (`\r`). По завершении выводятся только обнаруженные угрозы — чистые файлы не засоряют вывод.

**Альтернативные подходы:**
- Без CommandLineParser можно разобрать аргументы через `args[]` вручную. Это ~40 строк boilerplate против 7 атрибутов — нет смысла.
- Вывод в JSON вместо консоли — удобно для интеграции с другими инструментами, но выходит за рамки задачи.

**Безопасность:**
- Пути файлов передаются напрямую в `File.Exists` / `Directory.Exists` — path traversal невозможен, т.к. мы только читаем, не создаём файлы по переданным путям.
- Пользовательский ввод в промпте (`Q/D/S`) проверяется через `switch` с явными case — никакого eval или shell injection.

### 3.3 `Core/ScanResult.cs`

**Что делает:** определяет типы данных, которые используются как контракт между модулями.

```csharp
public enum Verdict     { Clean, PotentiallyUnwanted, Suspicious, Malicious }
public enum DetectionSource { Signature, Heuristic }
```

`Verdict` намеренно упорядочен по возрастанию опасности — это позволяет использовать сравнения (`r.Verdict >= Verdict.Suspicious`) вместо длинных `if/else`.

```csharp
public class ScanResult
{
    // Сигнатура
    public string Md5, Sha1, Sha256;
    public bool SignatureMatch;
    public string MatchedHash, MatchedAlgorithm;

    // Статика
    public bool IsPe, Is64Bit, IsSigned, SignatureValid;
    public string PackerName;
    public bool HasTls, HiddenImports;
    public List<string> SuspiciousImports, SuspiciousStrings;
    public List<SectionEntry> Sections;

    // Эвристика
    public int HeuristicScore;
    public List<HeuristicFlag> HeuristicFlags;

    // Итог
    public Verdict Verdict;
    public DetectionSource DetectionSource;
    public string Error;
}
```

`ScanResult` — это плоская структура, а не иерархия объектов. Это сделано намеренно: Program.cs должен обращаться к любому полю одним `r.FieldName`, а не `r.Static.Pe.Sections`. Читаемость вывода важнее архитектурной чистоты.

**Связи:** создаётся в `Scanner.cs`, заполняется тремя модулями, читается в `Program.cs` и `Quarantine.cs`.

### 3.4 `Core/Scanner.cs`

**Что делает:** единственная точка, которая знает обо всех трёх этапах и вызывает их в правильном порядке.

```csharp
public static ScanResult ScanFile(string filePath, HashSet<string> signatures)
{
    // Этап 1 — сигнатура
    var (md5, sha1, sha256) = SignatureScanner.ComputeHashes(filePath);
    var match = SignatureScanner.Check(md5, sha1, sha256, signatures);
    if (match != null) { /* заполняем и возвращаем */ return result; }

    // Этап 2 — статика (читает файл в память один раз)
    byte[] data = File.ReadAllBytes(filePath);
    var staticResult = StaticAnalyzer.Analyze(data, filePath);

    // Этап 3 — эвристика
    var heuristic = HeuristicEngine.Evaluate(staticResult);
    // ...
}
```

**Важный момент:** файл читается в память (`File.ReadAllBytes`) только один раз — на этапе статического анализа. Этап сигнатур работает через `FileStream` чтобы не загружать большие файлы целиком до проверки хэша. Лимит — 200 МБ, файлы сверх этого пропускаются с ошибкой.

**Сканирование папки** реализовано через `IEnumerable<ScanResult>` (генератор с `yield return`). Это позволяет Program.cs показывать прогресс в реальном времени, не ожидая конца сканирования всей папки.

Особенность C# 7.3: `yield return` не работает внутри блока `catch`. Решение — перехватить исключение в отдельную переменную `dirError`, а `yield return` вызвать уже после блока try/catch.

**Альтернативы:**
- Параллельное сканирование через `Parallel.ForEach` — ускорило бы обработку больших папок, но усложнило бы вывод прогресса и управление ресурсами. Для 3000 файлов последовательного подхода достаточно.
- Асинхронная модель (`async/await`) — аналогично, избыточно для задачи.

**Безопасность:**
- `UnauthorizedAccessException` перехватывается отдельно и записывается как ошибка в `result.Error` — программа не падает при отсутствии прав на файл.

### 3.5 `Core/Quarantine.cs`

**Что делает:** безопасно изолирует обнаруженный файл — XOR-шифрует и переносит в папку `quarantine\`, рядом сохраняет JSON-метадату для последующей идентификации и восстановления.

**XOR-шифрование:**

```csharp
private const byte XOR_KEY = 0xAA;

private static byte[] XorTransform(byte[] data)
{
    byte[] out_ = new byte[data.Length];
    for (int i = 0; i < data.Length; i++)
        out_[i] = (byte)(data[i] ^ XOR_KEY);
    return out_;
}
```

XOR симметричен: та же функция используется для шифрования и расшифровки. Цель шифрования — **не криптографическая защита**, а две практические вещи:
1. Файл нельзя случайно запустить двойным кликом.
2. Антивирус системы не срабатывает повторно на файл в карантине.

**Метадата (JSON):**

```json
{
  "OriginalPath": "C:\\samples\\trojan.exe",
  "QuarantinedAt": "2026-05-06T14:23:11",
  "Md5": "d41d8cd98f00b204e9800998ecf8427e",
  "Verdict": "Malicious",
  "HeuristicScore": 145,
  "SuspiciousImports": ["WriteProcessMemory", "CreateRemoteThread"]
}
```

**Почему Newtonsoft.Json а не ручная сериализация:** структура метадаты включает списки строк и nullable-поля. Написать корректный JSON-сериализатор вручную — это 60+ строк кода для функции, не связанной с кибербезопасностью. Библиотека справляется в одну строку.

**Ограничение:** если папка карантина находится на другом диске чем исходный файл, `File.Delete` после `File.WriteAllBytes` — единственный вариант (Move через диски не работает). Это текущее поведение, и оно корректно.

**Восстановление:**

```csharp
public static bool Restore(string quarFile)
{
    var meta = JsonConvert.DeserializeObject<QuarantineMeta>(File.ReadAllText(metaFile));
    byte[] original = XorTransform(File.ReadAllBytes(quarFile));
    File.WriteAllBytes(meta.OriginalPath, original);
}
```

`QuarantineMeta` — минимальный класс только с полем `OriginalPath`. Это осознанное решение: при десериализации через `dynamic` потребовался бы пакет `Microsoft.CSharp`, которого нет в SDK-style проектах на .NET Framework по умолчанию.

**Безопасность:**
- `SanitizeFileName` заменяет все символы из `Path.GetInvalidFileNameChars()` на `_` — имя файла в карантине не может содержать path traversal символы.
- Оригинальный путь хранится только в `.meta` файле, не в имени `.quar` — если `.meta` удалён, восстановить путь нельзя, но файл физически остаётся.

### 3.6 `Modules/SignatureScanner.cs`

**Что делает:** загружает базу хэшей малвари из `vvv.txt` в память и проверяет файл по трём алгоритмам.

**Загрузка базы:**

```csharp
var set = new HashSet<string>(1200000, StringComparer.OrdinalIgnoreCase);
foreach (var line in File.ReadLines(dbPath, Encoding.UTF8))
{
    var tab = line.IndexOf('\t');
    var hash = tab >= 0 ? line.Substring(tab + 1).Trim() : line.Trim();
    if (hash.Length > 0) set.Add(hash.ToLowerInvariant());
}
```

**Почему `HashSet` а не `List` или `Dictionary`:**
- `HashSet.Contains` — O(1) в среднем.
- `List.Contains` — O(n), при миллионе записей и 3000 файлов это 3 миллиарда сравнений.
- `Dictionary` дал бы O(1) но требует пары ключ-значение; здесь ключ и есть значение.

**Предварительная аллокация:** `new HashSet<string>(1200000, ...)` — начальная ёмкость под миллион+ записей. Без неё HashSet будет расти динамически, каждый раз пересчитывая внутреннюю таблицу. С предаллокацией — одно выделение памяти.

**Вычисление хэшей за один проход:**

```csharp
using (var md5 = MD5.Create())
using (var sha1 = SHA1.Create())
using (var sha256 = SHA256.Create())
using (var fs = new FileStream(..., FileShare.ReadWrite, 65536))
{
    var buffer = new byte[65536];
    int read;
    while ((read = fs.Read(buffer, 0, buffer.Length)) > 0)
    {
        md5.TransformBlock(buffer, 0, read, null, 0);
        sha1.TransformBlock(buffer, 0, read, null, 0);
        sha256.TransformBlock(buffer, 0, read, null, 0);
    }
    // ...
}
```

Файл читается один раз — три объекта `HashAlgorithm` обновляются одним и тем же буфером. Альтернатива — три отдельных прохода по файлу — в три раза медленнее по I/O.

**Поддерживаемые форматы базы:**
- `хэш` — одна строка
- `номер\tхэш` — с индексом через табуляцию (формат из условия задачи)

Поддерживаемые длины хэшей: MD5 (32 символа), SHA1 (40), SHA256 (64). Хэши другой длины не совпадут ни с одним из вычисляемых — не вызовут ошибку, просто не дадут совпадения.

**Безопасность:**
- `FileShare.ReadWrite` позволяет читать файл, который в данный момент используется другим процессом — без этого сканирование запущенных процессов невозможно.
- Сравнение хэшей регистронезависимое (`OrdinalIgnoreCase`, `ToLowerInvariant`) — исключает ошибки при смешанном регистре в базе.

### 3.7 `Modules/PeParser.cs`

**Что делает:** самописный парсер формата PE (Portable Executable). Читает заголовки файла, извлекает секции с их энтропией, таблицу импортов и флаг наличия TLS-директории.

**Почему самописный, а не библиотека:**
Задача требует только подмножества PE-формата: заголовки, секции, импорты, TLS. Реализация этого подмножества — около 250 строк. Тащить `PeNet` или `dnlib` ради чтения заголовков — избыточно и маскирует понимание формата.

#### Структура PE-файла (упрощённо)

```
[DOS Header]          ← 64 байта, содержит e_lfanew — смещение до PE заголовка
[DOS Stub]            ← код "This program cannot be run in DOS mode"
[PE Signature]        ← 4 байта: 0x50 0x45 0x00 0x00 ("PE\0\0")
[COFF Header]         ← 20 байт: тип машины, количество секций, размер Optional Header
[Optional Header]     ← 96 или 112 байт до DataDirectory
[DataDirectory[16]]   ← массив из 16 записей (RVA + Size), каждая 8 байт
[Section Headers]     ← идут сразу после Optional Header
[Section Data]        ← сырые данные секций
```

**Ключевое различие PE32 и PE32+:**

| Поле | PE32 (32-бит) | PE32+ (64-бит) |
|------|---------------|----------------|
| Magic | 0x010B | 0x020B |
| BaseOfData | есть (4 байта) | отсутствует |
| ImageBase | 4 байта | 8 байт |
| Stack/Heap fields | по 4 байта | по 8 байт |
| **Смещение до DataDirectory** | **96 байт** | **112 байт** |

Из-за этого смещения код явно проверяет `magic` и выбирает константу:

```csharp
private const int DIR_BASE_32 = 96;
private const int DIR_BASE_64 = 112;
// ...
int dirBase = is64 ? DIR_BASE_64 : DIR_BASE_32;
ms.Seek(optHdrStart + dirBase + 1 * 8, SeekOrigin.Begin); // Import directory
ms.Seek(optHdrStart + dirBase + 9 * 8, SeekOrigin.Begin); // TLS directory
```

**RVA → файловое смещение:**

```csharp
private static uint Rva2Off(uint rva, List<RawSection> secs)
{
    foreach (var s in secs)
    {
        uint span = Math.Max(s.VirtualSize, s.RawSize);
        if (rva >= s.VirtualAddress && rva < s.VirtualAddress + span)
            return s.RawOffset + (rva - s.VirtualAddress);
    }
    return 0;
}
```

RVA (Relative Virtual Address) — адрес относительно базы загрузки в памяти. Для чтения из файла его нужно перевести в файловое смещение через таблицу секций. `Math.Max(VirtualSize, RawSize)` — защита от случаев когда виртуальный размер секции больше сырого (BSS-секции).

**Разбор импортов (IMAGE_IMPORT_DESCRIPTOR):**

Каждый дескриптор — 20 байт. Поле `OriginalFirstThunk` указывает на массив записей Thunk. Каждая запись Thunk (4 байта для PE32, 8 для PE32+): если старший бит установлен — импорт по ординалу; иначе — RVA на `IMAGE_IMPORT_BY_NAME` (2 байта hint + null-terminated имя функции).

**Внутренний тип `RawSection`:**

```csharp
internal class RawSection
{
    public uint VirtualAddress; // нужен для Rva2Off
    // ...
}
```

Публичный `SectionEntry` не содержит `VirtualAddress` — он не нужен вызывающему коду. Если бы парсер работал с `SectionEntry`, пришлось бы либо добавлять лишнее публичное поле, либо RVA-трансляция была бы невозможна. Решение: внутренний тип с полным набором полей, публичный — без лишнего.

**Энтропия Шеннона:**

```csharp
public static double CalcEntropy(byte[] data, uint offset, uint length)
{
    int[] freq = new int[256];
    for (uint i = offset; i < offset + length; i++) freq[data[i]]++;

    double e = 0, n = length;
    for (int i = 0; i < 256; i++)
        if (freq[i] > 0) { double p = freq[i] / n; e -= p * Math.Log(p, 2); }
    return e;
}
```

Энтропия Шеннона измеряет «случайность» данных. Диапазон: 0 (все байты одинаковые) до 8.0 (равномерное распределение всех 256 значений). Зашифрованные или сжатые данные дают значения 7.0–7.9. Нормальный исполняемый код — 5.0–6.5.

**Безопасность:**
- Все обращения к массиву `data[]` ограничены явными проверками (`off < data.Length`, `ptr + step <= data.Length`) — нет выхода за границы.
- Исключения из парсера перехватываются в `Parse()` и записываются в `PeInfo.ParseError` — программа не падает на битых или намеренно испорченных PE-файлах.

### 3.8 `Modules/StaticAnalyzer.cs`

**Что делает:** оркестрирует пять видов статического анализа и возвращает `StaticResult`.

#### Пять видов анализа

**1. Цифровая подпись (WinVerifyTrust P/Invoke):**

```csharp
uint ret = NativeMethods.WinVerifyTrust(
    IntPtr.Zero,
    ref NativeMethods.WINTRUST_ACTION_GENERIC_VERIFY_V2,
    pData);

result.IsSigned      = ret != 0x800B0100; // TRUST_E_NOSIGNATURE
result.SignatureValid = ret == 0;          // S_OK
```

`WinVerifyTrust` — Windows API из `wintrust.dll`, доступен начиная с Windows XP. Используется P/Invoke (прямой вызов нативной функции из управляемого кода). Альтернатива — `X509Certificate.CreateFromSignedFile()` из BCL, но он бросает исключение вместо кода возврата при отсутствии подписи, что неудобно.

Структуры `WinTrustFileInfo` и `WinTrustData` маршализируются вручную через `Marshal.AllocCoTaskMem`. Освобождение в блоке `finally` — гарантирует отсутствие утечек памяти даже при исключении.

**2. Обнаружение упаковщика:**

Двухэтапное: сначала сравниваем имена секций (`UPX0`, `MPRESS1`, и т.д.), затем ищем байтовые маркеры в первых 512 КБ файла алгоритмом Boyer-Moore-Horspool.

**Boyer-Moore-Horspool** — улучшенный алгоритм поиска подстроки. Создаёт таблицу пропусков (`skip[]`) по символам паттерна, что позволяет пропускать несколько байт за одну итерацию. Средняя сложность: O(n/m) вместо O(n×m) у наивного поиска.

**3. Скрытые импорты:**

```csharp
bool hasGetProcAddress = false, hasLoadLibrary = false;
foreach (var imp in result.Pe.Imports)
{
    if (imp.Function.StartsWith("GetProcAddress", ...)) hasGetProcAddress = true;
    if (imp.Function.StartsWith("LoadLibrary",    ...)) hasLoadLibrary = true;
}
result.HiddenImports = hasGetProcAddress && hasLoadLibrary;
```

Программа, использующая `GetProcAddress + LoadLibrary`, разрешает адреса функций в рантайме — её IAT будет содержать только эти два вызова вместо реальных API. Это стандартная техника сокрытия зависимостей от статического анализа.

Дополнительный случай: если `NoImportDirectory == true` (импортов нет вообще), флаг ставится сразу — признак упакованного файла.

**4. Классификация импортов:**

```csharp
private static readonly Dictionary<string, int> DangerousApis = new Dictionary<...>
{
    { "WriteProcessMemory",   35 }, // инжект в память процесса
    { "CreateRemoteThread",   35 }, // создание потока в чужом процессе
    { "URLDownloadToFile",    30 }, // скачивание файлов
    { "WinExec",              30 }, // устаревший запуск процессов
    { "VirtualAlloc",          5 }, // слишком распространён у легитимных
    { "ShellExecute",          8 }, // есть у каждого файл-менеджера
    // ...
};
```

Веса выбраны с учётом распространённости API у **легитимного** программного обеспечения. `VirtualAlloc` используется .NET-рантаймом, браузерами, любым кодом с динамической памятью — его вес символический (5). `CreateRemoteThread` не имеет легитимных применений в обычном приложении — вес высокий (35).

**5. Сканирование строк:**

Извлекаются ASCII-строки (байты 0x20–0x7E, длина ≥ 5) и UTF-16LE строки (двухбайтовые символы из того же диапазона). Оба потока конкатенируются и проверяются регулярными выражениями.

```csharp
private static readonly (Regex rx, string label)[] StringPatterns =
{
    (new Regex(@"powershell\s+-[Ee]nc", RegexOptions.Compiled), "PowerShell encoded command (-enc)"),
    (new Regex(@"SOFTWARE\\...\\Run",   RegexOptions.Compiled), "Autorun registry key"),
    (new Regex(@"[A-Za-z0-9+/]{40,}={0,2}", RegexOptions.Compiled), "Base64-like encoded data"),
    // ...
};
```

`RegexOptions.Compiled` — компилирует регулярное выражение в IL-код при создании. Первый вызов медленнее, но последующие значительно быстрее. Оправдано, т.к. `StringPatterns` — статическое поле, инициализируется один раз для всего процесса.

**Почему убран паттерн `http://`:** присутствует в любом приложении, имеющем доступ к интернету. Генерировал бы флаг на каждый браузер, мессенджер и обновлятор. Заменён на `ftp://` (реже встречается в легитимных приложениях) и паттерн Base64 (специфичен для обфусцированных нагрузок).

**Безопасность:**
- P/Invoke с нативными структурами — единственное место в проекте с ручным управлением памятью. Каждый `Marshal.AllocCoTaskMem` имеет соответствующий `Marshal.FreeCoTaskMem` в `finally`.
- Строки, извлекаемые из тела файла, никогда не исполняются и не передаются в shell — используются только для regex-поиска.

### 3.9 `Modules/HeuristicEngine.cs`

**Что делает:** принимает `StaticResult`, применяет систему правил с весами, суммирует баллы, выносит вердикт.

**Пороги вердиктов:**

```csharp
private const int THRESHOLD_PUP        = 40;  // Potentially Unwanted Program
private const int THRESHOLD_SUSPICIOUS = 80;
private const int THRESHOLD_MALICIOUS  = 120;
private const double ENTROPY_HIGH = 7.2;
```

Пороги были пересмотрены относительно первоначального варианта (30/70/100) по следующим причинам:
- Порог 30 означал, что любой неподписанный файл с упаковщиком (UPX-фриварь) попадал в PUP.
- Порог энтропии 6.5 давал ложные срабатывания на сжатые ресурсы легитимных приложений.

#### Полная таблица правил

| Правило | Баллы | Обоснование |
|---------|-------|-------------|
| Файл не подписан | +10 | Снижен с 20 — очень распространено у freeware |
| Высокая энтропия секции (>7.2) | +20 | Снижен с 25, порог поднят с 6.5 |
| Секция W+X одновременно | +35 | Новое правило — шеллкод/инжект |
| WriteProcessMemory + CreateRemoteThread | +55 | Поднят с 30 — комбо должно давать больше чем по отдельности |
| PowerShell -enc | +30 | Поднят с 20 — специфично для малвари |
| Ключ автозапуска | +20 | Поднят с 15 |
| reg add / schtasks | +20 | Снижен с 40 — установщики тоже используют |
| Упаковщик обнаружен | +20 | Снижен с 30 — UPX у легитимных |
| Скрытые импорты | +30 | Поднят с 25 |
| TLS-колбэки | +20 | Без изменений |

**Защита от двойного счёта:**

```csharp
var counted = new HashSet<string>();
// Комбо-правило
if (hasWPM && hasCRT)
{
    score += 55;
    counted.Add("WriteProcessMemory");
    counted.Add("CreateRemoteThread");
    counted.Add("CreateRemoteThreadEx");
}
// Индивидуальные API — пропускаем уже посчитанные
foreach (var api in s.SuspiciousImports)
{
    if (counted.Contains(api)) continue;
    // ...
}
```

Без `counted` WPM получил бы +55 (комбо) и +35 (индивидуальный) — итого +90 вместо +55. Аналогичная логика для строковых паттернов: `alreadyCounted` содержит паттерны, уже обработанные специфическими правилами.

**Альтернативные подходы к эвристике:**
- **Машинное обучение** — более точно, но требует размеченной выборки и существенно усложняет код.
- **YARA-правила** — стандарт в индустрии, но требует внешней библиотеки и языка правил.
- **Байесовский классификатор** — теоретически элегантен, практически сложен в калибровке без хорошей тренировочной выборки.

Текущий подход — взвешенная сумма индикаторов — прост, объясним и настраивается без перекомпиляции (можно добавить новые правила, изменив константы).

## 7. Карта угроз безопасности

### Что уже защищено

**Path traversal при карантине:**
Функция `SanitizeFileName` заменяет все символы `Path.GetInvalidFileNameChars()` на `_`. Имя файла в папке `quarantine\` не может содержать `..`, `/`, `\` или другие path traversal символы. Оригинальный путь хранится только в `.meta` (не в именовании `.quar`).

**Выход за границы массива в PE-парсере:**
Каждое обращение к `data[]` предваряется проверкой: `off < data.Length`, `ptr + step <= data.Length`, `fo + 2 < data.Length`. Намеренно испорченный PE-файл не вызовет `IndexOutOfRangeException` — исключение будет поймано в `PeParser.Parse()` и записано в `ParseError`.

**Утечка нативной памяти в WinVerifyTrust:**
Три `Marshal.AllocCoTaskMem` освобождаются в блоке `finally` — гарантировано даже при исключении внутри `try`.

**Случайный запуск файла из карантина:**
XOR с ключом 0xAA делает файл нечитаемым как PE — Windows не сможет его запустить, антивирус системы не будет на него реагировать повторно.

**Инжекция через аргументы CLI:**
Строки из командной строки используются только как пути к файлам (`File.Exists`, `Directory.Exists`). Они никогда не передаются в `Process.Start`, `cmd.exe` или интерпретатор — shell injection невозможен.

### Что требует внимания

**Чтение всего файла в память:**
`File.ReadAllBytes(filePath)` загружает файл целиком. Лимит 200 МБ (`MAX_FILE_SIZE`) защищает от исчерпания памяти, но при одновременном сканировании нескольких больших файлов (если добавить многопоточность) суммарное потребление может быть значительным.

**TOCTOU (Time-of-Check / Time-of-Use):**
Между вычислением хэша файла и его чтением в память файл технически может быть изменён другим процессом. В контексте исследовательского сканера это несущественно, но в production-антивирусе требовало бы блокировки файла на всё время анализа.

**XOR — не криптографическая защита:**
Файлы в карантине защищены только от случайного запуска. Любой, имеющий доступ к папке `quarantine\`, может расшифровать файл, зная ключ 0xAA (он захардкожен в исходнике). Для production-решения нужно асимметричное шифрование с ключом, хранящимся вне папки карантина.

**Отсутствие верификации целостности метадаты:**
`.meta` файл можно подменить, указав другой `OriginalPath` — функция `Restore` запишет расшифрованный файл туда. Защита: проверка хэша перед записью и ограничение целевых путей.

**Base64-паттерн может давать ложные срабатывания:**
Регулярное выражение `[A-Za-z0-9+/]{40,}={0,2}` сработает на любую длинную строку из допустимых символов — например, длинный URL-параметр или GUID. Вес (15 баллов) достаточно низок, чтобы это не меняло вердикт в одиночку.

**Подпись проверяется через сеть:**
`WinVerifyTrust` по умолчанию может обращаться к серверам Microsoft для проверки отзыва сертификата (`fdwRevocationChecks = 0` отключает это). Текущая конфигурация не делает сетевых запросов, что правильно для офлайн-сканера.

## 8. Глоссарий

**PE (Portable Executable)** — стандартный формат исполняемых файлов Windows (.exe, .dll, .sys). Содержит заголовки с метаданными и секции с кодом и данными.

**RVA (Relative Virtual Address)** — адрес относительно базы загрузки модуля в памяти. Не совпадает с файловым смещением из-за разных выравниваний секций.

**IAT (Import Address Table)** — таблица импортов PE-файла. Содержит адреса функций из внешних DLL, используемых программой.

**TLS (Thread Local Storage)** — механизм для хранения данных, специфичных для потока. TLS-директория в PE может содержать колбэки (`TLS callbacks`), которые выполняются **до** `AddressOfEntryPoint` — популярная точка для антиотладочного кода.

**Энтропия Шеннона** — математическая мера «случайности» набора байт. Значение 0: все байты одинаковые. Значение 8.0: идеальное равномерное распределение. Зашифрованные данные: 7.0–7.9.

**Упаковщик (Packer)** — инструмент, сжимающий или шифрующий исполняемый файл. При запуске «заглушка» распаковывает оригинальный код в память. UPX, MPRESS — легитимные упаковщики. Themida, WinLicense — коммерческие протекторы, популярны у малвари для обхода детектирования.

**Process Injection** — техника внедрения кода в чужой процесс. Классический паттерн: `VirtualAllocEx` → `WriteProcessMemory` → `CreateRemoteThread`. Детектируется по наличию обоих API в одном файле.

**Process Hollowing** — создание легитимного процесса в suspended-состоянии, замена его кода вредоносным через `NtUnmapViewOfSection` + `WriteProcessMemory`, возобновление. Один из паттернов обхода мониторинга.

**Authenticode** — механизм цифровой подписи исполняемых файлов Windows, основанный на X.509 сертификатах. Проверяется через `WinVerifyTrust`.

**WinVerifyTrust** — Windows API для проверки цифровой подписи файлов. Возвращает 0 при валидной подписи, `0x800B0100` (`TRUST_E_NOSIGNATURE`) при её отсутствии.

**P/Invoke (Platform Invocation Services)** — механизм вызова нативных Windows API функций из управляемого C# кода через атрибут `[DllImport]`.

**HashSet** — коллекция уникальных элементов с O(1) поиском (в среднем). Используется для базы сигнатур и для отслеживания уже подсчитанных API в эвристике.

**Boyer-Moore-Horspool** — алгоритм поиска подстроки. Строит таблицу пропусков по символам паттерна, пропуская несколько позиций за итерацию. Используется для поиска байтовых маркеров упаковщиков.

**XOR-шифрование** — побитовая операция исключающего ИЛИ. Симметрична: `data XOR key XOR key == data`. Используется для обфускации файлов в карантине — не криптографически стойко.

**TOCTOU (Time-of-Check/Time-of-Use)** — класс уязвимостей: состояние объекта проверяется в момент T1, используется в момент T2, между которыми другой процесс мог его изменить.

**Ординальный импорт** — импорт функции по числовому идентификатору вместо имени. В PE-файле запись Thunk с установленным старшим битом означает ординальный импорт. Используется для обфускации — статически сложнее определить, что именно импортируется.
